# SQLite 查询与裁剪优化验证（2026-10-21）

版本 `20261021.4` 在同机、相同离线基准下明显降低了统计、正常裁剪及并发请求延迟。统计结果、API、保留策略与 schema 12 的列结构不变。

## 实现与升级

- 复用按 Key、模型计算的 Token 聚合中的请求数，删除重复分组。总和仍由 SQLite 计算，NULL 用量和未知用量计数不变；模型计数按 UTF-8 字节序保持 SQLite BINARY 排序。
- 新增 Key、状态及 Token 聚合所需的索引，统计读取覆盖索引，无需读取含正文的表列。
- 新增精确 UTF-8 字节表达式索引，让正常裁剪的字节汇总读取索引中的值。该值由 SQLite 随写入和事务维护；没有进程内统计缓存，直接 SQL 写入、跨连接、回滚和重启保持一致。
- 启动时在列迁移后幂等建立索引。旧库首次升级需要扫描日志建立索引，会增加启动耗时和磁盘使用；新增索引也有写入维护成本。没有重写日志正文或更改裁剪顺序。

索引使用 SQLite 的[覆盖索引](https://www.sqlite.org/queryplanner.html#covidx)与[表达式索引](https://www.sqlite.org/expridx.html)机制；表达式与现有 UTF-8 字节计算保持一致。

## 验证与限制

性能回归检查实际执行 SQL 的查询计划及虚拟机指令，要求统计和正常裁剪不读取正文表列，不依赖特定索引名或机器耗时阈值。同时验证空库、NULL、Unicode 排序、跨连接提交可见性、回滚、重启和 UTF-8 裁剪结果。

结果来自本机暖缓存、小样本与合成数据，不能代表生产吞吐量或 p95。写入探针使用 BEGIN/ROLLBACK，不包含耐久提交和 fsync；正常裁剪数据未超正文容量上限，不能用于推断大批字节超额删除的性能。没有测量冷启动建索引耗时、锁竞争或索引磁盘增量。未进行真实付费上游测试，未部署生产。
